The Portal Error: "Predicted values must be in range [0, 1]"

Several participants received the validation rejection "Predicted values must be in range [0, 1]" when uploading files to DrivenData.

Root Causes:

  • Negative Nodata Sentinels: GDAL and raster export tools frequently write default float32 sentinels (such as -3.4028235e+38 or -999999.0) into unmasked regions. DrivenData's ingestion engine performs a global min/max check on the unmasked raster array; negative values fail this check immediately.
  • Uncontrolled NaNs: Files that declare NaN values where the validator expects numeric probabilities or zero-filled cells trigger range parsing failures.

The Guaranteed Fix Applied in This File:

  • All-Finite Zero Outside Encoding (-zeros): Every single pixel across the entire $3730 \times 3292$ grid is an all-finite float32 value in $[0.0, 1.0]$. Cells outside the footprint are set to 0.0 rather than sentinels or NaNs.

  • No Nodata Tag: The GeoTIFF carries no nodata sentinel tag, preventing any parser from injecting negative values.

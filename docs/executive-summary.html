Why the Portal Error Occurred and How It Is Fixed

The Error

On the DrivenData submission form, submitting certain files triggered:

"Predicted values must be in range [0, 1]"

Why It Happened

  1. Nodata Sentinel Leaks: Standard GeoTIFF writers often write a nodata tag using large negative values (e.g. -3.4028235e38 or -999999.0). DrivenData's ingestion script reads the array without masking nodata and checks min(array) >= 0 and max(array) <= 1. When a negative sentinel is present, the range check fails immediately.
  2. NaN Outside Bounds: If NaNs outside the official bounding footprint are not handled properly by the portal reader, numpy comparisons return invalid range flags.

How Our File Eliminates the Error

  • All-Finite Zero Outside Encoding (-zeros): The entire 3730 × 3292 grid is encoded as clean, finite float32 numbers strictly within [0.0, 1.0]. Cells outside the footprint are set to 0.0.
  • Zero NaNs: nan_count = 0 everywhere in the raster.
  • No Nodata Tag: No negative float sentinel exists in the TIFF metadata (nodata = null).
  • Byte Verification: The file was validated by re-reading the exact bytes from disk (validate.validate_submission), confirming 14/14 checks pass:
    • Band count: 1
    • Dtype: float32
    • CRS: EPSG:32611
    • Dimensions: 3730 × 3292
    • Geotransform: (100.0, 0.0, 243350.0, 0.0, -100.0, 4508550.0)
    • Range: min = 0.0, max = 1.0

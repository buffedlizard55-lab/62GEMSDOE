3.2 The new idea, stated once

The Lahontan datum is not one surface. It is a stack of nested shorelines at different elevations and therefore of different ages. This session detected that stack from the DEM (1455, 1389, 1325, 1278 m; block support 7, 7, 12, 7 of 323 twenty-kilometre blocks) instead of assuming a single datum band, then demanded that a flagged step lie on one common line with flagged steps on at least one other level. Because shorelines are nested, the naive test ("the same place on two levels") is geometrically wrong — a fault is a line, and it crosses each level at a different point — which is why the test here is a Hough collinearity vote with sign agreement. Independent cross-check that the detection is real: the strongest level, 1325 m, matches both the published Lahontan highstand band and the 1,332–1,347 m block isobase an earlier session fitted independently (lane62/evidence/isobase.json, 86 blocks).

3.3 Three defects this session found and fixed

  • IR-62-REG-01 — tools/fetch_registry.py wrote every blob to f"{repo}__{basename}", so

all docs/downloads/submission.tif files collapsed onto one filename: 46 of the first 51 fetches overwrote each other. The uniqueness gate would have compared against a fraction of the registry while reporting the full count. Fixed; the re-fetch returned 476 distinct rasters.

  • IR-62-REG-02 — src/gems62/uniqueness.py raised ValueError on a shape mismatch, so a

single 32×48 format-test image killed an unattended uniqueness run. Now skipped and counted in the verdict.

  • IR-62-H62R-03 — the first version of this lane's own isolation statistic counted a

radius-3 disc including its boundary, so two dots exactly 300 m apart (kernel weight exactly 0) were reported as "sharing a disc" — the receipt said 39 % of dots shared one while a k-d tree said the minimum nearest-neighbour distance was exactly 300.000 m and the mean self-kernel was 0.000000. The statistic now measures the thing that costs mass, and the two agree: 0 dots with kernel overlap.

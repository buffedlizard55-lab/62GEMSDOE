3. The arithmetic — this is the explanation

The published metric is DTI = T / (T + 0.2·F + 0.8·(N − T)) with T = TP_w, F = FP_w, N = total kernel-weighted hidden-truth mass. For isolated unit dots every dot contributes its credit to T and the complement to F, so T + F = M − E where E is dot-to-dot overlap (E ≈ redun·M). Hence

DTI  =  c·M / ( 0.2·(M − E) + 0.8·N )          c = mean 300 m kernel credit per dot

Four consequences, each of which is a design rule:

(a) DTI → 5c as M → ∞. The score is asymptotically five times the mean per-dot credit. Nothing else matters at large mass. #1 at 0.4133 therefore implies c ≳ 0.0827; the top-5 cut-off 0.3333 implies c ≳ 0.0667.

(b) The hidden truth mass is bounded: N ≤ 13,688 cells. The 0.2778 file is a thinning of the 0.2600 file (44,090 → 37,654 dots). Thinning cannot add credit, so 0.26·(0.2A₁ + 0.8N) ≥ 0.2778·(0.2A₂ + 0.8N) with A = M(1 − redun), which solves to N ≤ 13,688 — MEASURED here, independently of the sibling repository's 10,000–14,100 range. At the planning value N = 12,000 the champion implies c = 0.1254 and T = 4,723, i.e. 39 % kernel-weighted recall of the faults that are absent from the USGS/INGENIOUS catalogue.

(c) At identical mass, placement quality spans 3.6×. GEMSDOE34 h34-scatter carries the same 37,654 dots and scores 0.0778 → implied c = 0.0344. The champion at the same mass implies c = 0.1254. Mass is not the lever; detector quality is the entire game.

(d) Isolation is a hard rule, and it is the one thing the registry proves outright. Across the 87 score-anchored rasters (research/registry_measurements.json):

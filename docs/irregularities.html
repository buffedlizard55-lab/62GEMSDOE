Irregularities, defects and traps — flagged, with what was done about each

The brief asks for irregularities to be flagged rather than smoothed over. These are ordered by how much damage they could do.

1. The portal error you hit: "Predicted values must be in range [0, 1]"

Diagnosis. The official spec asks for a single-band float32 raster with values in [0, 1] [OFFICIAL, competition page 967]. Two writing habits violate it while looking correct on screen: a float32 sentinel such as -3.4028235e38 (survives as an outlier inside the valid footprint), and a NaN nodata tag (the reader returns NaN, which is not in [0, 1]). The defective artifact from the earlier session — gems32-h19-5-smoothmaxcov-44090.tif — is one of these, and it is quarantined by standing rule: never ship, never re-emit.

What is done about it. One writer, one code path, and the file is re-opened from disk and re-counted before anything is published (grid.check_submission). The current file reports nodata = null, nan_count = 0, n_outside_0_1 = 0, all_finite = true. The two mechanisms are structurally absent, not merely avoided.

3. The registry uniqueness tripwire is density-blind — a shared-tool defect, fixed and reported

Defect. The brief's tripwire is "> 70 % of your dots within 3 px of one registry raster's dots ⇒ duplicate". Measured here: 13gems_20261001_r13-lattice-s5_v2 carries 206,895 dots, which dilates to 112 % of the 5.17 M-cell footprint, so its 3 px neighbourhood covers the map and any emission scores ≈ 1.0 on the tripwire.

Proof, not assertion. A uniform-random 1,660-dot control (build/controls/poisson_1660_seed7.tif, seed 7) scores dot_overlap_within_kernel = 0.9982 against that same raster. A tripwire that fires on Poisson noise cannot certify a duplicate.

Fix (in scripts/check_uniqueness.py, reported here rather than forked). The verdict now additionally requires a symmetric overlap — the Jaccard index of the two 3 px-dilated dot masks, |A ∩ B| / |A ∪ B|, threshold 0.25. It is 1.0 for a re-run of the same lane and ~0.01 for a sparse emission against a dense lattice. The asymmetric fraction is still reported as a diagnostic, because it is what the brief names.

Result for the current file: UNIQUE-VS-REGISTRY across 289 rasters — worst rank correlation −0.065, worst Jaccard 0.030, and the asymmetric maximum of 1.00 attributable to the lattice raster above.

4. The catalogue-based holdout anti-selects novelty — so it is not a score

Measured three independent ways (hypotheses.md, "the validation trap"): a sibling repository measured ρ = +0.087 between its catalogue-hidden proxy and the live leaderboard; its Poisson control (0.098) beats an artifact that scored 0.2778 live (0.019); and this repository's own Poisson control (0.0669) beats the same artifact (0.0067) by 10×.

Consequence, stated in every document that carries the number: the holdout is a bug screen, a leakage canary and a null generator. It is never written as a score, and it is never used to promote or reject a file.

5. Owner-reported scores are claims, not receipts

The scores the user has quoted (0.2778, 0.3774, …) are recorded here as OWNER-REPORTED. No organizer receipt, e-mail or exported leaderboard row is present in this repository, and the competition pages do not expose them to this sandbox. They are used only to rank the group's own artifacts against each other, which is what the user asked for, and never as an evaluation of a file produced here. If a receipt exists, it should be committed as evidence/ and this file updated — it would be the first ORGANIZER-CONFIRMED number in the repository.

6. Submission note length

The stated limit is 140 characters; the site has previously accepted 177–200 [OWNER-REPORTED]. This repository keeps ≤ 140 because that is the stated limit. The current note is 128 characters.

−32767 nodata sentinel to −32766 when rounding to decimetres. Handling it as metres made every elevation gate false; the fix is in read_z() and in the fetch writer (sentinel written after the clip, readers mask ≤ −32000).

  • Run 38169049665 is recorded as success with no artifact — a silent-empty result. It is

kept in evidence/ precisely because "success" was not the same as "produced data".

  • dem_transport.json records resampling: "as-is", i.e. the mosaic is not reprojected here; the

tiles are already EPSG:32611 at 25 m.

  • Coverage after run 38169727207: 6 tiles, valid fraction 0.8088 (was 0.590 with 5). The

per-block coverage map has not been re-verified since the 6th tile landed — a gap in this session's evidence, listed in next-steps.md.

9. What the organizers will and will not tell us — read this before trusting any local score

  • They will not share the data sources, fault types or coverage behind the test faults beyond

the problem description [OFFICIAL, thread 11527 — chrisk-dd, 2026-09-23].

  • Phase 2 uses a test set updated by expert review of all Phase 1 submissions [OFFICIAL, same

post]. Phase 1 predictions therefore influence final evaluation even when they do not score well — which is the only sound argument for spending a Phase-1 slot on a file whose local evidence is thin, and which is why this file's verdict is "low-risk novelty probe" rather than "do not submit".

10. A suspicious statistic in this file's own output

The 221 traces have a median length of 1.3 km (max 5.6 km). Real fault traces are usually longer, so the binding constraint is probably the trace-stopping rule rather than the geology. Flagged as unresolved; see next-steps.md.

IR-62-16 — the protocol's 3-px uniqueness leg is unsatisfiable; independently re-proven

A pure-random 10,000-dot off-catalogue field (seed 11, zero geological information) puts 84.12 % of its dots within 3 px of 13gems_20261001_r13-lattice-s5_v2, 84.12 % of …zerofill, and 76.58 % of 13gems-composite-plus — i.e. it trips the protocol's 70 % duplicate rule against 3 of 79 comparators. IR-62-H62R-02The catalogue-based holdout is structurally 0 for any field that obeys the catalogue exclusion. Pooled DTI 0.000000 over 81,993 withheld positives with a random-dot control at 0.0287 on the same folds — the field scores below its own control, which is the signature of the exclusion, not of a bad field. IR-62-H62R-03A statistic can be wrong in the direction of flattering the job. This lane's own isolation check counted dots inside a radius-3 disc whose boundary it included, so two dots exactly 300 m apart — where k(300 m) = 0 exactly — were reported as sharing a disc, and a dot was counted as its own neighbour. The receipt therefore read "39 % of dots share a 300 m disc" while an independent k-d tree read "minimum nearest-neighbour 300.000000 m, mean self-kernel 0.000000". Both were computed from the same raster. The check now measures kernel mass received from other dots and excludes self: 0 of 14,765 dots has any overlap. Rule: state the boundary convention in the statistic's own name or note, and cross-check an isolation claim two independent ways.

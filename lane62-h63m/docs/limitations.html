Limitations — what is in the way of winning

  1. No organizer receipt exists for any file in this repository. Every DTI on this site is either a proxy measurement against a free truth set or a model projection. Until a file is uploaded, the calibration constant r rests on nine owner-reported scores that this project cannot independently verify.
  2. The only proxy truth set is a 1:750 k geologic compilation. The USGS SGMC maps bedrock faults; it under-represents the young, small, basin-floor faults that a geothermal exploration programme cares about, and it favours rough terrain. A detector that finds mountains will score well on it whether or not it finds faults.
  3. The official feature stack does not generalize spatially. Measured: AUC 0.50 on held-out 512 px blocks. Either the 100 m resampling destroys the signal, or fault location at pixel scale is not recoverable from these bands. Both readings are recorded; they cannot be separated without the organizer's truth.
  4. The sandbox cannot reach drivendata.org, USGS hosts, or any non-GitHub host. The DEM, the feature stack and the proxy catalogue were all obtained through sibling GitHub repositories. New external data has to be fetched the same way (or through the repository's dem-fetch GitHub Actions workflow, which does have unrestricted egress).
  5. 2 CPUs and 3 GB of RAM. A 19-band, 5.16 M-cell design matrix is 578 MB in float32; several candidate designs had to be re-written to stream channels one at a time. Anything larger than a shallow boosting ensemble is out of reach here.
  6. The weekly submission cap is a hard constraint the lanes cannot see. Promotion to a real slot is a separate selector step; this session produces and ranks, it does not submit.
  7. The datum lane cannot resolve what it is asked to resolve at 100 m. Measured: 10.3 m of isobase residual scatter against a 3 m method resolution. Lidar at 1 m, transported through the dem-fetch workflow, is the only way to test the lane as written.

What to do next, in priority order

  1. Spend one slot on the identification experiment: upload this file, then a λ = 0.5 re-emission and a null-mass probe. Three returns identify T, K and F exactly and turn every projection on this site into a measurement.
  2. Build a second proxy truth set that is not a bedrock compilation — the INGENIOUS project's own interpretation products, or the Nevada Bureau of Mines and Geology Quaternary fault database rasterised on this grid.
  3. Fetch 1 m / 3 m lidar through the dem-fetch workflow and re-run the datum lane on it. This is the only way to test the assigned hypothesis rather than a 100 m surrogate of it.
  4. Add orientation-consistency along strike: the current channels are pointwise. A fault is a curve with slowly varying azimuth, and a Hough / tensor-voting step on top of the belief field is the obvious next detector.
